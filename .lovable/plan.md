

## Diagnosis

The red X on the GitHub commit is **not** caused by the `bg-card` removal in `Portfolio.tsx`. That edit is syntactically clean — no missing imports, no unused vars, no type errors.

The actual build failure (reproduced locally with `npm run build`):

```
[vite]: Rollup failed to resolve import "@tanstack/query-core"
from "node_modules/@tanstack/react-query/build/modern/index.js"
```

**Cause:** `@tanstack/react-query` (^5.83.0) declares `@tanstack/query-core` as a required dependency. It is listed in `package.json` but **`@tanstack/query-core` is missing from `node_modules/@tanstack/`** (only `react-query` is present). On Vercel, the install step produces the same broken tree, so Rollup fails to resolve the import and the build aborts. Lovable previews still work because Vite's dev server is more forgiving than Rollup's production bundler.

This is a dependency hygiene issue, not a code bug. No syntax / type / lint problem exists in `Portfolio.tsx`.

## Fix

Add `@tanstack/query-core` as an explicit dependency so the install tree always contains it on Vercel.

### Step 1 — Add the missing peer
- Add `"@tanstack/query-core": "^5.83.0"` to `package.json` (matching the `react-query` major/minor it ships with).
- This forces both the lockfile and Vercel's `npm install` to materialize the package, allowing Rollup to resolve the import.

### Step 2 — Verify the production build locally
- Run `npm install` then `npm run build`.
- Confirm: `✓ built in <time>` with no Rollup resolution errors.

### Step 3 — Sync to GitHub
- The `package.json` + lockfile change auto-pushes through Lovable's GitHub sync, producing a new commit.
- Vercel re-runs the build with the fixed dependency tree → green check → deploy.
